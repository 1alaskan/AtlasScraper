# Adams County scrape, group `county_commercecity`

Step 4 scrape, run 2026-10-31 (UTC). Five build-verdict sources from the step 2 back-test: Adams County Planning Cases (rank 1), Adams County Building Permits (rank 2), Adams County Assessor Property Sales joined to the assessor tables (rank 12), Commerce City Active Development layers (rank 7) and the Adams County PrimeGov meeting portal (rank 14). Scripts are in `scripts/` (standard-library Python, shared helpers in `scripts/cc_common.py`), raw pages under `raw/<source_slug>/` (git-ignored), one CSV per source in this folder.

## Assumptions

- Dates in the ArcGIS layers are stored as local midnight in UTC milliseconds (06:00 or 07:00Z); converting in UTC gives the right calendar day. `record_date` is `DATE_OPENED` (planning), `CaseOpened` (permits), `saledt` the deed date (sales; the recording date `docdt` is an extra column), `APPLIED_DT` (Commerce City).
- The county layers (planning, permits) cover unincorporated Adams County only, so `city` is set to `Unincorporated Adams County`; neither layer carries a zip, so `zip` is blank.
- Still-active 2023 records ride along with the default pull: planning cases whose `RECORD_STATUS` is not a closed, cancelled, denied, expired, withdrawn or approved status; permits whose `ApplicationStatus` is not Case Finaled, Case Closed, Closed, Closed Approved, C of O Issued or CO Issued.
- Personal names. Planning `RECORD_NAME` and Commerce City `DESCRIPTIO` are project names that often carry the applicant's surname ("Garcia Gazebo Setback Variance", "Hardin Subdivision Final Plat"); `cc_common.looks_like_individual_project` strips the case vocabulary, addresses and case numbers and blanks a name that leaves one or two plain words with no business term. It errs on the side of blanking (a few two-word development names such as "Welby Junction" are lost). Deed parties use `looks_like_individual_party`, which splits on `&`, `and`, `;` and `,`, strips undivided-interest and care-of fragments, and blanks the whole name when any part reads as a person or a personal trust (institutional trusts such as "WILMINGTON TRUST NA" are kept). Free-text descriptions are kept as the record gives them, trimmed to 500 characters, with e-mail addresses and phone numbers removed by `cc_common.clean`; a surname inside a long description (for example "Box Elder Creek Ranch PUD, Witt Amendment") can survive, so the description column is not a clean field for publication.
- `industrial_use` is a keyword test (`cc_common.INDUSTRIAL_WORDS`: industrial, warehouse, manufacturing, distribution, flex, data center, plant, process, equipment, crane, tank, silo, compressor, dust collection, paint booth, boiler, generator, logistics, cold storage, truck, recycling, pipeline, substation, hangar, I-1/I-2/I-3 and similar) over the name, description, type and use fields. It is a wide net for ranking, not a classification.
- The Adams County Parcels layer has no land-use or zoning field (the discovery row said it did). Land use comes from the assessor `Property_Values` table (`ACCTTYPE`: Residential, Commercial, Industrial, Agricultural, Exempt, State Assessed, Possessory, Producing Mine; `VACIMP`: V or I) and zoning from the county `Zoning` polygon layer at the parcel centroid, which only carries districts for unincorporated land (inside a city the polygon is the city name).
- No em dashes are written; `clean()` replaces them with hyphens.
- Flag rules for the no-valuation permit layer follow the brief: tier A = non-residential construction class (new, addition, change in use, alteration) or construction work type (tenant finish, warehouse, core and shell, office) with an industrial word in the description, building use or work type; tier B3b = any other non-residential permit on industrial property (`BuildingUse` Industrial, description prefix `IND`, or census code 20). Tier B3a cannot be applied without valuations.

### Adams County planning cases
**Source:** Adams County Community and Economic Development, Accela Planning module mirrored to ArcGIS Online ("Planning Cases Eye on Adams", item dc2027641ca845ae973b71314c76f14e). `https://services3.arcgis.com/4PNQOtAivErR7nbT/arcgis/rest/services/Planning_Cases/FeatureServer/0`. Route: the documented ArcGIS REST query API, `resultOffset` paging, 2,000 rows a page, 2 requests plus a count and a schema check. No bulk download exists for this layer (it is not on the county open data hub); Accela Citizen Access is browser-only and was not opened.
**Verdict:** pass. Names projects and often the operator (`RECORD_NAME`, `DESCRIPTION`), parcel number and point on every row, daily refresh.
**Terms and robots:** `services3.arcgis.com/robots.txt` returns HTTP 403 "Invalid URL" (none served). The item is shared public with an empty licence field; the county's sibling assessor items are CC BY 4.0 and the county site's disclaimer is liability-only. One request a second, user agent `step4-research-pull/1.0`.
**Rows:** 2,712 written; the source's own `returnCountOnly` for the same filter is 2,712. Filter: `DATE_OPENED >= 2024-01-01`, plus 2023 cases whose status is still open (385 rows, 127 distinct cases). No rows left out (no residential screen on planning records; residential plats and variances are in the file with `industrial_use` N).
**Date range:** 2023-01-03 to 2026-10-29 (opened), every month present, 8 to 210 rows a month (the 210 in April 2025 and 195 in July 2026 are multi-parcel cases: one row per parcel).
**Flagged:** 2,712 Y under `all planning and development cases`. `industrial_use` Y on 765 rows (PRE 338, RCU 196, PRC 92, PLT 55, VSP 33, EXG 18, TVM 16, other 17). By type code: PRE 666, RCU 375, PLN 336, LIQ 312, PLT 298, VSP 266, PRC 192, TVM 82, PUD 59, VAC 45, MEL 41, PRA 22, EXG 18.
**Null rates:** company_name 21.3% (579 rows: the record name read as a person's name and was blanked), site_address 15.8% (the layer's `ADDR_FULL_LINE` is blank or "0 -" on those), record_date 0%, description 2.0%, zip 100% (not carried).
**Duplicates:** 247 record_ids appear more than once (1,662 rows; 1,297 distinct cases). The layer holds one row per parcel, so a multi-parcel case repeats with a different `parcel_number`. Kept so the count matches the source; de-duplicate on `record_id` for case counts.
**Fields:** industrial_use, record_type_code, status, status_date, parcel_number, latitude, longitude, accela_url (the Accela Citizen Access record, manual lookup only), parser_version.
**Join key:** `parcel_number` (13-digit assessor parcel number, joins to the assessor tables and the sales file), `record_id` (joins to PrimeGov hearing titles, which quote PLN/PRC/RCU numbers), latitude/longitude on every row. `site_address` is free text and inconsistent ("5675 Pecos ST", "5751 N Pecos ST").
**Refresh:** `python3 scripts/pull_adams_county_planning_cases.py` (about 10 seconds; `--since YYYY-MM-DD` writes an incremental file `scrape_adams_county_planning_cases_since_<date>.csv`, `--fresh` ignores the same-day cache). Daily layer; weekly is enough. Re-pull everything each time because status changes on old cases.
**Gotchas:** (1) One row per parcel, see duplicates. (2) The name screen is aggressive: 579 of 2,712 names blanked, among them a handful of company-named cases whose names are two plain words. Full names are in the raw cache if a case needs to be resolved by hand. (3) LIQ and MEL licence cases (353 rows) are noise for this pipeline and can be dropped on `record_type_code`. (4) `RECORD_TYPE` spelling varies ("TVM - Temporary Use", "TVM - Temporary Use Permit", "Conceptual Review" without a code); `record_type_code` normalises it.
**Not pulled:** nothing in scope is missing. Case narratives and application PDFs live on the county's Current Land Use Cases page and in Accela, not in the layer.

### Adams County building permits
**Source:** Adams County Community and Economic Development, Accela Building module mirrored to ArcGIS Online ("Building Permits Eye On Adams", item ad7a332efe0146f5bb9e5cacc912de0d). `https://services3.arcgis.com/4PNQOtAivErR7nbT/arcgis/rest/services/Building_Permits_Eye_On_Adams/FeatureServer/0`. Route: ArcGIS REST query API, 2,000 rows a page, 7 requests. No bulk download; Accela browser-only.
**Verdict:** pass with the structural limits the back-test found: no valuation, no applicant, owner or contractor field; the tenant or company appears only inside the free-text description, and a conservative extractor found one on 40 rows.
**Terms and robots:** as for the planning layer (no robots.txt on the host, public item, empty licence field).
**Rows:** 1,352 written of 13,125 in the source filter (`CaseOpened >= 2024-01-01` plus 2023 permits still active: 199 rows carried in). Residential rows left out: 11,773, by building use: blank use 6,313 (rooftop solar, re-roofs, siding, water heaters, home boilers and furnaces, identified from the description, work type and census code), Residential 4,644, Single Family 742, Agricultural Business 44 (county-labelled "RES -" barns and fences), Mobile Home 19, Commercial 11 (multi-family apartment buildings). Agricultural barns without the county's RES label are kept with flag N. The source count for the filter was 13,125 and 13,125 rows were fetched; the CSV holds the non-residential subset by design.
**Date range:** 2023-01-06 to 2026-10-29 (opened), every month present, 8 to 56 non-residential rows a month.
**Flagged:** 341 Y of 1,352. `tier A: non-residential construction with industrial word, no valuation in layer`: 252 (building use Commercial 145, Industrial 105, Agricultural Business 2). `tier B3b: industrial property, non-residential, no valuation in layer`: 89 (Industrial 87, Commercial 2 with an IND description prefix). Everything else N with a blank rule (1,011: signs 231, fences 93, commercial re-roofs 86, cell tower work 52, meters, HVAC swaps and the like).
**Null rates:** company_name 97.0% (40 names extracted from descriptions, role `tenant`: Craft Labeling, CFM Company, Helena Agri-Tech, Crescent Electric, ABCO Contracting, Gallery Carts, Target Sortation Center, Bellio Trucking and so on), site_address 0%, record_date 0%, description 0%, zip 100% (not carried), square_feet blank on 92% (the layer populates `TotalSQFT` on the larger tenant finishes only).
**Duplicates:** 31 record_ids appear twice or more (71 rows): multi-address permits the layer repeats, with the same description. Kept; de-duplicate on `record_id` for permit counts.
**Fields:** permit_type (always BDP), type_of_work, class_of_work, building_use, census_code, square_feet, status, subdivision, parcel_number, industrial_property (Y/N), latitude, longitude, accela_url, parser_version. `record_type` is "type of work / class of work".
**Join key:** `parcel_number` (joins to the assessor tables and the planning file), `site_address` (`CombinedAddress`, upper case, suite rarely present, "5725 PECOS ST, STE 203 ST" style artefacts), latitude/longitude on every row. Matching a company has to go through the description text or the parcel.
**Refresh:** `python3 scripts/pull_adams_county_building_permits.py` (about 15 seconds; `--since` for an incremental file, `--fresh` to refetch). Daily layer; weekly is enough. Re-pull the last 90 days at least: status and description change after opening.
**Gotchas:** (1) The county applies residential census codes ("34 - Res. Add and Alter Only") to commercial work, so the residential screen uses the census code only when building use is blank; Commercial and Industrial rows are dropped only when they are multi-family housing. (2) Descriptions carry a prefix (`COM -`, `IND -`, `RES -`, `AG BUS -`) on about 60% of rows and it is the best single use signal; `industrial_property` uses it. (3) Three descriptions carried phone numbers and one an e-mail address; `clean()` removes them. (4) The name extractor only fires after "for", "tenant:", "owned by" or "dba" and rejects generic first words, so it misses names given without a trigger ("CEMEX Denver Terminal", "Molson Coors"); the description column still carries them for a text search.
**Not pulled:** nothing in scope is missing. Trade permits are in the same layer (permit type BDP covers all), valuations do not exist in the layer, and applicant or contractor names exist only in Accela (browser-only, not opened).

### Adams County assessor property sales
**Source:** Adams County Assessor via county GIS, "Property Sales" table (item c518fafaabf8476fb83d5a7b7b1aa7be). `https://services3.arcgis.com/4PNQOtAivErR7nbT/arcgis/rest/services/Property_Sales/FeatureServer/0`. Route: ArcGIS REST query API, 2,000 rows a page, 29 pages for the 2024-onward sales. Joins on the same host: `Property_Values/FeatureServer/0` (whole table, 190,105 rows, 96 pages, for `ACCTTYPE` and `VACIMP`), `Parcels/FeatureServer/0` (POST lookups by parcel number with `returnCentroid`, 31 batches of 100, for address, city, subdivision and centroid; owner fields never requested), `Zoning/FeatureServer/0` (1,265 polygons, point-in-polygon at the centroid), `Property_Improvements/FeatureServer/0` (12 batches, building descriptions). The hub CSV download of the sales table was not used because the filtered REST pull is a tenth of the size and the joins need the REST tables anyway.
**Verdict:** pass as a filtered feed for purchases by operators (the back-test's CEMCO and RK Industries deeds are both in the file, flagged Y: reception 2025000044328, 9410 Heinz Way, $29,250,000, grantee PMDEN LLC c/o JFE Shoji America Holdings Inc; reception 2025000035204, 3301 Lewiston St, $23,600,000, grantee RK 3301 Lewiston EAT LLC and co-owner). Weak for naming operators: most grantees are holding LLCs.
**Terms and robots:** no robots.txt on the host (HTTP 403). The sales and values items are CC BY 4.0 (licence field on the ArcGIS items; attribution to Adams County). One request a second.
**Rows:** 1,603 written of 56,616 sales dated 2024-01-01 onward (the source's own count for `saledt >= 2024-01-01`; 56,616 fetched). Left out: 52,570 sales on parcels whose assessor account type is Residential; 2,443 sales on other non-residential parcels with no commercial or industrial county zoning (Agricultural 1,693, Exempt 748, Producing Mine 1, State Assessed 1). Kept: land use Commercial 1,463, Industrial 123, plus 17 Agricultural or Exempt parcels inside unincorporated I-1, I-2, C-0 or C-4 zoning.
**Date range:** 2024-01-03 to 2026-10-27 (deed date), every month present, 24 to 81 rows a month. No future-dated rows in the kept set (the table has typos up to 2029 on residential rows).
**Flagged:** 296 Y under `sale 2M+ on industrial or commercial-industrial parcel` (465 rows are at or above $2M; the rest are retail, hotel, office or multi-parcel commercial with no industrial building). Industrial or commercial-industrial means account type Industrial, county zoning I-1/I-2/I-3, or an assessor building description matching warehouse, manufacturing, industrial, flex, distribution, cold storage, equipment, service garage, truck, lumber, hangar or similar (`industrial_use` Y on 781 rows under that wide test). Flagged rows by jurisdiction: Aurora 79, unincorporated 91, Commerce City 86, Thornton 15, Brighton 5, Bennett 5, Arvada 6, others 9.
**Null rates:** company_name (grantee) 29.9% (476 blanked as individuals or personal trusts, 3 blank in the source), grantor 35% (556 blanked, the rest blank in the source), site_address 14.0% (parcel has no situs address, or no Parcels row for the number), record_date 0%, zip 99.9% (`LOCZIP` is blank in the Parcels layer), jurisdiction 0.5%.
**Duplicates:** 23 record_ids (reception number / parcel) appear twice (46 rows): the same deed carried on two assessor accounts of one parcel. Kept.
**Fields:** sale_price, grantor, grantee, deed_type (SWD 1,015, QC 229, WD 139, others), recording_date, reception_number (Landmark Web lookup by hand), account_number, parcel_number, land_use, vacant_or_improved, lot_size, lot_measure, actual_total_value, zoning (unincorporated only), zoning_class, jurisdiction (from the zoning layer: Unincorporated 483, Commerce City 346, Aurora 241, Thornton 167, Westminster 144, Brighton 90, Northglenn 58, Federal Heights 33, Bennett 22, Arvada 8, Lochbuie 3), improvements (building descriptions with square feet and year built), industrial_use, keep_reason, subdivision, latitude, longitude (parcel centroid), parser_version. `description` summarises deed type, price, grantor, land use and buildings.
**Join key:** `parcel_number` to the planning and permit files; `grantee` to SOS registrations for the holding-LLC resolution; `reception_number` for the deed.
**Refresh:** `python3 scripts/pull_adams_county_property_sales.py` (about 5 minutes, most of it the Property_Values spine; `--since` for an incremental file, `--fresh` to refetch the spine and lookups). Weekly. The 2M filter is applied at flag time, not at pull time, so the file keeps every commercial or industrial sale for the ranking.
**Gotchas:** (1) The join spine is `Property_Values`, not `Parcels`; a parcel with several accounts takes the non-residential account's class. (2) Multi-parcel deals repeat the same price on every parcel row (the $24.3M Standard Denport purchase appears on four Aurora parcels), so sum prices per reception number, not per row. (3) Grantee strings carry "C/O" care-of lines and undivided-interest fragments; `grantee` is the raw string, screened for persons but not normalised. (4) City zoning is not available from the county layer, so `zoning` is blank inside cities; `land_use` and `improvements` carry the industrial test there. (5) `Property_Improvements` is the assessor's building inventory and lags construction, so a new building on a vacant purchase shows no improvements.
**Not pulled:** residential sales (by design), deed images (Landmark Web is browser-only and behind a Cloudflare challenge), owner names from the Parcels layer (not requested).

## QA summary (all four written CSVs)

- Each CSV starts with the 17 shared columns in the brief's order; `flag` is Y or N only; no description over 500 characters; no em dashes; no e-mail addresses or phone numbers.
- Rows dated before 2023-01-01: none in the three county files; 4 in the Commerce City file (kept on the task's "keep every row" instruction, see the card).
- Row counts against the source: planning 2,712 = 2,712; permits 13,125 fetched = 13,125 (1,352 non-residential written); sales 56,616 fetched = 56,616 (1,603 kept), Property_Values 190,105 = 190,105, zoning 1,265 = 1,265; Commerce City 556 features fetched = 127 + 429 (499 distinct keys written).
- Person-name spot checks: 50 random `company_name` values read by eye in each of the planning, permits, sales and Commerce City files after the final screens; none read as a private individual. The screens blanked 579 planning names, 476 grantees and 556 grantors.
